# 雀伴 · Riichi Companions

在浏览器里与本地机器人、LLM 或外部 Agent 打日麻。牌局由麻将引擎推进，模型通过工具看牌、聊天和提交动作。

项目面向本机使用：Node.js 服务管理牌局与 Agent，Three.js 渲染立体麻将桌和牌，React 显示角色立绘、聊天与操作面板。

## 功能

- 四人日麻，支持一局战、东风战、半庄战、自定义 1–16 局，以及赤五、食断和多人荣和设置。
- 玩家座位可选择真人、本地机器人、LLM 或外部 Agent；真人座位可绑定教练。
- Codex、Qoder 启动脚本，以及 OpenAI 兼容和 Anthropic 工具调用接口。
- 公共聊天、座位私聊、角色表情和分页气泡；聊天窗口可拖动，局外闲聊也会保存。
- 明牌回放、逐步查看、进度跳转与倍速播放；对战结束时自动保存到历史记录。
- 全身立绘、头像、背景和自动朝向翻转；同一素材可分配给多个角色。
- 固定透视的 3D 牌桌、圆角牌体、侧壁和阴影；点击手牌出牌，悬停抬牌，支持键盘操作。回放使用同一套渲染。
- 自动存档、暂停与恢复、连接诊断、终端日志和牌局记录导出。

和牌由引擎判定，只在可以和牌时提供自摸或荣和；不提供自由推牌和诈胡罚分。本项目不是 WRC 官方规则预设。

自定义局数在「这张桌 → 房规 → 对局长度」设置。固定局数按实际开局次数计算，和牌、流局均计一局，连庄也计数。达到局数后，确认结算即结束对战；负分仍会提前结束。一局战使用同样的计数方式，东风战、半庄战保留按场风轮转的规则。

桌心菜单的「终止对局」会作废整桌对战并重置点数，取消 Agent 任务，不发送结束事件、不结算排名、不存入历史对战。全局聊天保留。

正常和牌或流局后，LLM 角色会根据公开战况简短复盘，并谈谈对其他牌友这一局的印象。内容保存在全局聊天和回放中；打牌任务优先，未发言的复盘被打断后会重新排队。

## 快速开始

### 环境

- Node.js **22.12 或更高版本**。
- pnpm。
- 接入本机 Agent 时，另需安装对应 CLI 并完成其登录或服务配置。

### 开发运行

克隆仓库时一并初始化第三方子模块：

```bash
git clone --recurse-submodules https://github.com/PerviousFurther/llm-playing-mahjong.git
cd llm-playing-mahjong
```

如果已经克隆过仓库，先执行：

```bash
git submodule update --init --recursive
```

然后在项目根目录执行：

```powershell
pnpm install
pnpm dev
```

浏览器打开 **http://localhost:3000**。开发模式由同一个服务加载 Vite，无需另外启动前端。

### 数据与临时目录

默认存档和历史牌谱保存在项目的 `data/`；脚本 Agent 的任务文件保存在系统临时目录，任务结束后清理。可在启动前指定：

```powershell
$env:MAHJONG_DATA_DIR = 'D:\MahjongData'
$env:MAHJONG_TEMP_DIR = 'D:\MahjongTemp'
pnpm dev
```

相对路径以项目根目录为准。首次指定不存在或空的数据目录时，会复制原 `data/`（含模型配置、上传素材和牌谱），保留原文件；已有内容的目标目录直接使用，不覆盖。切换目录前先停止服务，新目录不要放在原 `data/` 内。后续启动需使用同样的环境变量。

### LLM 读取工具

MCP 和 HTTP 工具模型默认接收精简轮次信息，决策任务附带自己的手牌。按需调用 `get_turn`、`get_hand`、`get_player`、`get_messages`。`analyze_actions` 比较合法弃牌或吃碰杠的向听数、未见进张和门前／役牌限制；并非完整防守算法、所有役种检查或胜率预测。`unseen` 包含他人暗牌与死牌墙，不等于山中剩余枚数。本机 Agent 仅支持 MCP。

首次可以直接点击「先和本地牌友玩一局」，不需要模型账号。点击角色名片更换玩家类型或素材，点击桌心查看牌局菜单。

### 构建运行

```powershell
pnpm build
pnpm start
```

仍使用 http://localhost:3000。服务绑定 `127.0.0.1`，默认只接受本机访问。

修改端口，例如在 PowerShell 中：

```powershell
$env:PORT = '3001'
pnpm dev
```

仓库的 `pnpm-workspace.yaml` 已允许 `esbuild` 构建脚本。如果 pnpm 仍提示 `ERR_PNPM_IGNORED_BUILDS`，检查该文件是否完整；也可运行 `pnpm approve-builds` 批准 `esbuild`，再安装依赖。

## 配置牌友

开局前点击角色名片，选择玩家类型：

| 类型 | 用途 |
| --- | --- |
| 由我游玩 | 浏览器手动操作，可配置私人教练 |
| 本地牌友 | 内置机器人，无需设置模型连接 |
| LLM 自动游玩 | 模型通过 API 或本机脚本操作 |
| 外部 Agent | 自行实现客户端，通过外部接口操作 |

牌局内锁定玩家、模型连接配置和房规。出牌时直接点击手牌；立直先点击「立直」，再选牌。牌局暂停后点击「继续牌局」恢复。

对局结束后点击「再开一桌」重新配置并开局。新对局会清空上一场的游戏上下文。

### 本机 Codex / Qoder

现成脚本位于：

- [shortcut/codex](shortcut/codex/README.md)
- [shortcut/qoder](shortcut/qoder/README.md)
- [shortcut/dsh](shortcut/dsh/README.md)

使用步骤：

1. 修改启动脚本中的 CLI 可执行路径、模型名称和思考深度。仓库当前的 PowerShell 脚本包含开发者本机路径，使用前需替换。
2. 在角色连接设置中选择「本机 Agent 进程」，启动方式选「启动脚本」。
3. 填写脚本的**绝对路径**。
4. 保存配置，点击「检查连接」。无需开局，检查会实际调用模型，可能产生费用。
5. 将该座位设为「LLM 自动游玩」，然后开局。

支持 `.ps1`、`.bat`、`.cmd` 和 `.sh`。Windows 的 `.sh` 需要 Bash，可在运行选项中指定解释器。模型参数由脚本控制；界面的角色性格用于调整口吻。

代理地址在连接设置的「运行与网络」中填写，例如 `http://127.0.0.1:7890`。游戏向子进程传入标准代理环境变量，是否使用由对应 CLI 决定。

### API 模型

选择 OpenAI 兼容或 Anthropic 服务，填写接口地址、模型和密钥，保存后检查连接。服务需要支持 **function calling / tool use**；仅能返回普通文本的接口无法执行当前的工具决策。

API 模型与本机 MCP 共用工具定义和动作校验，无需把本机 MCP 端口暴露给远端服务。

本机模型同样选择「OpenAI 兼容 API」，开启「连接前启动本机服务」，填写 [llama 启动脚本](shortcut/llama/README.md) 的绝对路径。游戏复用脚本 runner 启动服务，自动获取地址和模型，并共用 API 决策与工具执行流程。同一脚本可供多个角色共用，模型跨任务保留，退出游戏时结束进程树。已手动启动的服务关闭启动选项，直接填写 API 地址即可。

连接页面的「本机模型服务」显示服务状态、模型、地址、启动进程 PID、运行与启动耗时、共用角色、当前请求和等待任务，以及累计请求数和耗时。共用启动配置的角色使用同一份统计，游戏服务重启后统计清零。任务耗时仅统计成功任务，排除排队和模型启动；Token 用量及生成速度仅在模型服务返回相应数据时显示，不额外测速。没有执行或等待任务时可停止游戏启动的服务，下次连接会自动启动；手动运行的外部服务不提供停止按钮。

## Agent 如何工作

```text
牌局决策 / 聊天 / 事件
        ↓
每个角色的任务队列
        ↓
本机 CLI + MCP，或 API 工具调用
        ↓
游戏校验动作、发布消息并更新牌桌
```

每个角色一次执行一个任务。出牌和吃碰杠响应优先于闲聊，必要时取消正在执行的聊天；尚未回复的聊天保留到之后处理。
同一回复渠道的待处理聊天与牌桌事件会合并成一条请求，并按顺序列出通知。公共聊天、不同对象的私聊与教练消息分别处理。空闲角色使用 80 毫秒的合并窗口，牌局决策立即入队，不等待这个窗口。控制台会显示合并的通知数量。

本机 CLI 每个任务启动一次，完成后结束进程。Codex 使用临时会话，Qoder 禁用会话持久化，不恢复上一任务的会话。旧配置统一切换为 MCP；自定义脚本须适配 MCP 工具调用。

| 工具 | 功能 |
| --- | --- |
| `get_turn` | 当前轮次、合法动作和最近事件 |
| `get_hand` | 自己的手牌、向听数和进张 |
| `get_player` | 指定玩家的公开牌局信息 |
| `get_messages` | 近期聊天，支持增量读取 |
| `analyze_actions` | 比较合法弃牌与副露 |
| `discard` / `riichi` | 用 `tile` 参数打牌或立直 |
| `chi` / `pon` / `kan` | 用 `meld` 参数吃、碰或杠 |
| `pass` / `declare_win` / `abort` / `continue` | 提交其他合法牌局动作 |
| `send_message` | 发送公共聊天或私聊，可多次调用 |
| `finish_task` | 结束聊天、事件或教练任务 |

当前任务只提供允许的动作和参数。成功提交一个牌局动作后任务结束；吃碰后需要弃牌时，游戏会发送新的决策任务。连接检查要求实际调用 `get_turn`，文字确认不算通过。

### 输入与隐私

模型收到简短房规、当前牌桌、自己的手牌及最近一巡的对话。最近一巡按最近四次摸牌划定，公共与私聊记录各最多 32 条，不传事件时间戳；所有弃牌和副露仍保留在状态中。

模型看不到其他人的未公开手牌、牌墙或不属于自己的私聊。公共消息进入共享上下文，Agent 公共发言不会自动触发所有模型回复；LLM 私聊另一个 LLM 会触发对方回复。

本机管理页面可查看全桌私聊记录。当前不收集模型思考链。本机 CLI 是本地程序，工具权限限制不等同于操作系统沙箱。

完整脚本契约与 MCP 配置见 [Agent 接入文档](docs/agent-process.md)。

## 素材

角色素材放在 `asset/<角色目录>/`，由 `metadata.json` 描述名称、朝向和头像。常用表情文件为 `idle.png`、`thinking.png`、`hello.png`、`laugh.png` 和 `unhappy.png`；详细字段及兼容文件名见 [立绘元数据](docs/agent-process.md#立绘元数据)。

也可以通过界面选用素材或上传图片。全身立绘放在麻将桌后方，由桌面遮住下半身。

## 存档与调试

| 路径 | 内容 |
| --- | --- |
| `data/game.json` | 当前对局、全局聊天、事件与私聊存档 |
| `data/replays/` | 对战结束时保存的历史牌谱 |
| `data/profiles.json` | 角色连接配置，可能包含 API 密钥 |
| `data/media.json` | 素材选择 |
| `data/uploads/` | 界面上传的图片 |

启动时加载当前存档。桌心菜单的「看看牌局记录」→「历史对战」可选择已结束的对战，在原来的麻将桌场景中播放，四家手牌全部公开。「回看本次对战」直接打开本次对战对应的历史记录。进行中的对战不提供明牌回放。支持上一步、下一步、拖动进度和 0.5–4 倍速播放。角色之间的聊天也作为回放节点出现，聊天窗口与角色气泡随进度更新。回放时不能发送消息或操作手牌；点击「返回实时牌桌」退出。观看历史不会暂停实际牌局，需要停下来观看时先暂停牌局。

点击回放中的角色卡片或播放控制区的「角色记忆」，可查看截至当前位置的记忆和更新历史，按 `hh:mm:ss` 显示更新时间，并跳转到对应更新节点。记忆窗口可拖动、缩放；向前或向后拖动回放进度时，当前记忆同步变化。尚未发生的更新不会提前显示。

正常结束的对战立即保存到 `data/replays/`；结束后的复盘与聊天继续补入同一条历史记录，开新对战后固定。作废的对战不保存历史。牌谱记录每局的初始手牌及后续摸牌、打牌、副露等变化，读取回放时还原各步骤的完整明牌状态。回放数据仅本机管理员可以读取。历史牌局可以导出为 JSON，新版导出文件也可在回放界面导入；旧版只含公共事件的导出文件缺少摸牌与完整手牌，无法恢复明牌回放。升级前保留在 `data/game.json` 的已结束对战会自动补存到历史。

全局聊天保存局内与局外消息，开新对局不清空；聊天窗口显示最近 500 条聊天以及当前对局的近期事件。模型上下文仍按当前对局隔离，不会收到历史对局的全局聊天。升级前已经被清空的消息无法恢复。

要清空当前对局，先停止服务，再备份并删除 `data/game.json`；保留其他文件即可保留连接与素材配置。
此操作也会清空保存的全局聊天。历史回放单独保存在 `data/replays/`，需要清空历史时另行备份并删除其中的 JSON 文件。

运行服务的终端显示任务排队、执行、工具调用、进程退出与耗时。连接错误可在角色面板展开诊断。技术超时为 120 秒，失败后牌桌等待重试，不自动替玩家出牌。

PowerShell 日志选项：

```powershell
# 完整 CLI 输出，包括输入回显
$env:MAHJONG_AGENT_OUTPUT = 'raw'
pnpm dev

# 隐藏 CLI 输出，保留任务状态与错误日志
$env:MAHJONG_AGENT_OUTPUT = '0'
pnpm dev
```

不设置该变量时默认输出精简日志。以上变量影响启动后的服务进程。

## 代码布局

| 目录 / 文件 | 职责 |
| --- | --- |
| `src/` | React 页面、牌桌、聊天和设置 |
| `server/room.js` | 麻将引擎、状态、动作与存档 |
| `server/agents.js` | 角色队列、任务优先级与结果提交 |
| `server/agent-worker.js` | 任务执行、取消与超时 |
| `server/agent-context.js` | 输入压缩与简短房规 |
| `server/agent-prompt.js` | Markdown 格式的模型提示词 |
| `server/agent-tools.js` | 共用工具定义与校验 |
| `server/mahjong-mcp.js` | 通用 MCP 服务 |
| `server/script-agent.js` / `server/api-agent.js` | 本机脚本与 API 调用 |
| `shared/` | 规则、牌名及回复格式 |
| `shortcut/` | CLI 启动脚本 |
| `vendor/majiang-core/` | 日麻引擎子模块 |
| `public/tiles/` | 日麻牌面素材子模块 |
| `asset/` | 角色立绘与背景素材 |

接入新的 CLI，优先适配启动脚本，复用通用 MCP。添加工具时修改共用工具定义与游戏提交逻辑，API 和 CLI 都能使用。
